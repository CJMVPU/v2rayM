# 上游合并规则

生效日期：2026-10-21。产品范围来自用户最新决定：**只支持 Xray，移除
sing-box 兼容代码**。本文件优先于仓库旧文档里的多内核描述；更改此范围
需要用户明确要求。保留 fork 与 upstream 关联不等于恢复上游全部功能。

## 允许引入与必须排除

| 上游变化 | 本仓库处理 |
| --- | --- |
| Xray 协议、XHTTP、TLS/Reality、DNS、路由修复 | 审查后移植，验证现有节点配置和原生 TUN |
| 通用解析、存储、安全、取消、下载校验修复 | 保留必要依赖，测试失败与回滚路径 |
| sing-box 模型、生成器、转换、SRS、下载、统计或 TUN 桥 | 排除，不保留空实现或改名后的兼容层 |
| Mihomo/其他内核的启动、自动选择、更新或打包 | 排除；不能用它们作为不支持节点的后备 |
| Avalonia/WPF、Windows/Linux 图形项目 | 不恢复；SwiftUI 是唯一产品界面 |
| 订阅页面、独立连接按钮、可拖动窗口尺寸 | 不恢复 |
| 原生 helper、签名/授权、可信内核替换 | 保留本地设计，安全修复逐项移植，禁止用任意路径启动替代 |
| 通用格式解析（例如包含 Xray 可用节点的链接） | 可以保留，但必须按 Xray 支持范围校验，不能启动其他内核 |
| 旧用户数据里的未知协议/旧内核编号 | 保留数据；拒绝不支持的使用请求，不能误解释为 Xray 或静默删除 |

## 操作顺序

1. 记录当前提交、上游范围及工作区变更；保留用户未提交修改。阅读根目录
   `AGENTS.md`。先列出涉及产品边界的文件和需要移植的修复。
2. 在可回退的分支完成合并。对删除/修改冲突逐个决定；本地删除的多内核文件
   不因上游更新而自动恢复。不使用全仓库 `--theirs` 或覆盖本地架构的操作。
3. 检查导入→保存→配置生成→启动→切换→停止→更新→失败恢复的完整路径。
   内核注册表、默认映射、更新目录、UI 和打包清单必须一致，仅允许 Xray。
4. 运行 `python3 scripts/check-macos-product-boundaries.py`。它扫描有效源码、
   资源和打包入口，不把历史测试报告当作运行代码。新增文件也必须扫描。
5. 运行后端测试、原生客户端测试、helper 测试；重新发布后端、构建/签名应用，
   运行隔离目录里的本地回环验证，检查安装包内核内容与源代码一致。
6. 真实 TUN 联网需要确保其他软件已退出 TUN/系统代理。记录启动、唯一 Xray
   核心、DNS/路由、停止恢复；不能拿配置检查或旧报告代替新版本联网验收。
7. 交付说明列出移植项、刻意排除项、测试结果和未验证项。提交/推送/正式发布
   按用户授权执行，不能把开发签名本机包描述为公开公证发行。

## 回归必须覆盖

- 系统代理/TUN 互斥；连续点击、启动失败、切换失败和退出恢复。
- 原生 TUN 单一 Xray 数据链路，helper 最小权限接口与调用方验证不退化。
- 核心与 Geo 更新保留校验、进度、替换、重启、成功清旧版、失败恢复。
- 配置读写保留未编辑字段；不支持的内核/协议在后端被拒绝。
- 节点配置按钮固定显示，未选中禁用；底栏不跳动；日志不拼接、不整批清空。
- 窗口固定尺寸，圆角边框均匀，悬停不挤动布局，提示不改变布局。
- 本地 Xray 修复版必须保留独立的上游版本与补丁标识；同版本不被官方包覆盖。
  用户确认的新版本规则是“等待验证”：收到用户要求后审查该版本并运行绑定、回环和
  原生 TUN 回归，再放行升级。合并不能移除该保护或用版本号变大代替兼容验证。

## 不能用来绕过规则的方式

不要删除测试、关闭校验或增加禁用引擎白名单来消除合并冲突。
不要仅隐藏 UI，却保留可通过 API、自动更新或旧配置启动的另一个内核。
不要重编号持久化枚举，不要为“清理”而删除用户节点或 v2rayN 数据。
