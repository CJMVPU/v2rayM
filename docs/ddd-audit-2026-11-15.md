# DDD 全程序架构审查（2026-11-15）

## 审查目标

目标是使全程序的业务规则、用例顺序与基础设施可分别演进，为合并上游、增加功能和优化运行提供边界。
采用模块化单体，保留 macOS SwiftUI + Xray、ServiceLib/WebAPI fork 与独立签名 helper。
不要求把平台 I/O、协议解析或 UI 布局机械搬进领域层；它们仍有明确的基础设施/展示所有者。

`WebApiEndpoints` 继续以旧 HTTP 契约调用 facade；`V2rayRuntime` 构造共享运行上下文并组合用例。
普通查询投影不获得写权限。状态健康发布比较快照身份并原子提交，不能利用旧观察覆盖新的连接。
AppModel 的 `refresh` 和各主题闭包仅做读取、代际校验及 UI 发布；轮询的恢复/清理分派在应用层。
helper 不引用普通后端领域/应用程序集，避免把特权能力放入普通用例依赖图。

## 审查中补齐的遗漏

- 独立 Geo 更新原先在 facade 中编排核心重启和补偿，现接入 `GeoUpdateRunService`。
- TUN 开关原先单独修改/保存 Config，现通过 `SettingsEditorService` 保留字段并补偿保存失败。
- 原生初始连接、设置后观察任务均纳入退出排空，避免退出与迟到结果竞争。
- 原生周期轮询与更新终态判断已从 AppModel 提取；失败观察不作为网络清理授权。
- Swift 边界扫描除 import 方向外，也拒绝通过 Foundation 直接使用典型磁盘、进程和网络 API。

## 上游与兼容性核对

领域和应用模块无 ServiceLib/ASP.NET/SwiftUI/AppKit 引用；C# 应用项目只引用领域项目，Swift 同样。
ServiceLib 接缝及合并注意事项列于 [扩展指南](ddd-extension-guide.md)，未导入新的上游提交。
HTTP DTO、持久化枚举与数据库表结构不因本次分层改变；完整上游实体仍由适配器保留。
版本保留 `VERSION` 的 0.4.4，未增加引擎、GUI 平台或 helper 权限。

原生 View 文件的布局没有在本次 DDD 工作中修改。窗口、列宽、标题栏操作、底栏和 hover 规则继续由既有视图实现；
日志渲染与字体资源保留，领域化只改变观察/保留规则的所有者。

## 验证范围与可复查证据

源代码审查不能替代构建或真实网络结果。最终证据位于
`artifacts/reviews/2026-11-15-ddd/`，由以下记录分别证明：

- `final-validation.json`：实际测试计数、边界检查、构建与烟雾结果，以及未执行事项。
- `final-product/verification.json`、`product-manifest.json`：同源码构建、签名和包内回环；缺失或未通过即未完成对应验收。
- `final-restore-api-smoke.log`：临时目录备份/恢复、明确重启、鉴权及 SSE 后设置保存。
- `final-*-tests.log`：后端、ServiceLib、Swift Native/helper 和脚本测试原始结果。

真实 TUN、正式签名公证、安装、提交、推送和发布未作为本地架构改造自动执行。
真实网络恢复仍需在没有其他 VPN/TUN 占用网络时单独验收；本地测试和开发签名不证明该项。
