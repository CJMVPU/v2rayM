# DDD 架构与模块边界

本次迁移采用模块化单体，沿用 SwiftUI → 本机 WebAPI → ServiceLib → Xray 和签名 helper。
产品范围、安全与上游合并规则仍由 AGENTS.md 和 upstream-merge-policy.md 决定。
扩展方式见 [扩展指南](ddd-extension-guide.md)，全程序职责与验证范围见 [架构审查](ddd-audit-2026-11-15.md)。

## 已实现的边界

- `v2rayN/V2rayM.Domain` 是无 NuGet、ServiceLib、ASP.NET 依赖的领域程序集。
  Runtime 保存运行状态与设置应用决策；Updates 决定候选是否有资格进入暂存；
  Telemetry 维护按时间加权的流量窗口。它们均已接入生产调用链。
- `V2rayM.Application` 已承载订阅新增、编辑、查询、删除与后台更新用例，依赖领域模型、仓储、请求头验证和共享写锁端口。
  后台更新通过操作租约端口参与关闭排空，共用配置写锁，按更新→保存配置→更新时间戳→发布变化顺序执行。
  上游下载尚不支持取消时等待其返回，再检查取消，不能提前释放租约或将取消误报完成。
  删除在生命周期锁→配置写锁下判定实际运行节点和选择节点归属；停止失败则不删除，删除后保存分组选择。
  WebAPI 的 `Adapters/Subscriptions` 负责 ServiceLib 持久化与 HTTP 契约映射。编辑的读取、合并、保存与回读
  在同一写锁内进行；适配器原位更新读取的实体，保留未来上游新增字段。
- `ProfileCatalogService` 已承载分组选择、节点导入、复制、跨组移动、重排与列排序。
  应用层仅使用节点 ID、领域排序/移动枚举和仓储端口；上游枚举映射与实体读取由适配器负责。
  相关存在性校验、当前分组读取、排序快照和写入位于同一共享写锁，避免校验和写入之间的竞态。
  重排只读取节点和排序值，不再构造带订阅名称和流量计数的完整 UI DTO。
- `ProfileRemovalService` 在生命周期锁下编排停止、删除、选择恢复和重启，配置写锁在启动之前释放。
  只依据实际存在的节点计算删除影响，故障但仍拥有进程时也必须先停止；停止失败不删除，重启失败保留已删除事实。
- `ProfileExportService` 在共享配置写锁内捕获一次节点快照并编排分享链接、内部链接和客户端配置导出。
  格式生成与上游配置构造留在适配器，应用层不暴露 ProfileItem。
- `ProfileEditorService` 已接管节点编辑身份绑定、存储归属保留、协议不可变、组依赖校验、持久化和重启编排。
  `ProfileEditing` 保存节点验证规则；适配器编辑会话保留完整上游文档，仅将验证事实和持久化结果传入应用层。
  编辑在生命周期锁下执行，读取旧节点与保存共用配置写锁，保存失败不重启、不发布成功变化。
- `SpeedTestCoordinator` 统一测速准入、任务互斥、取消和停机操作租约；准备读取与执行持有同一租约，维护不能在两者之间替换配置。
  单节点延迟入口同样由协调器取得租约，避免请求层和后台任务嵌套共享租约阻塞独占维护；每次运行通过适配器创建使用当前配置的上游测速服务。
  非 TCP 测试仅接受 Xray 支持的节点；TCP 测试不启动代理内核。
- `ProfileMaintenanceService` 编排清理和分组生成；存在性检查与生成写入共用写锁。
  批量清理通过上游可选筛选接口保留不支持、复杂、当前选中及正在运行的节点；筛选同时影响重复候选与匹配基准。
  清理先获取生命周期锁，避免筛选期间连接身份切换。
- `ProfileQueryService` 使用独立应用读取模型，列表过滤与稳定排序、分组计数不依赖 HTTP DTO。
  分组源不读取测速/流量扩展，详情与分享链接保持完整上游契约并由读取适配器提供。
- `RoutingRuleService` 已承载规则保存、追加、移动、删除与下载，`RuleOrder` 定义插入位置语义和边界。
  规则对象由适配器保留完整字段，规则编辑只给缺失或重复身份分配新 ID，不再调用会重编号全部规则的批量导入函数。
  活动规则依据持久化前后内容判断重启需求；无变化重排不会触发重启。设置事务仍包围规则应用，保留原有快照/恢复。
- `RoutingProfileService` 已承载配置新增、编辑、激活、删除后的回退和预设导入。
  新配置不能继承输入的活动身份，编辑不能覆盖存储身份、顺序和未暴露字段；应用层共享写锁包围读取、修改和活动配置比较。
  配置级编辑同样保留规则 ID；重复激活、相同内容保存和只改非活动配置不会重启内核。
  完整上游文档仍由适配器持有，预设下载/存储仍复用 ServiceLib，现有设置快照和恢复事务继续包围整个用例。
- `SettingsTransaction`、`SettingsApplyService`、`SettingsRecoveryService` 统一设置快照租约、应用和失败补偿。
  事务按生命周期锁→共享写锁取得恢复日志与快照，直到应用/恢复结束才释放生命周期锁；取消不能提前中断补偿。
  存储和进程接口在 WebAPI 适配，应用程序集不依赖 Config、HTTP DTO 或进程 API。
  回滚区分配置恢复、旧运行意图恢复和附加文件恢复；附加恢复失败仍尝试恢复配置，但不能重新启动旧核心。
  保留健康旧进程须核对节点、启动时间和全部进程 ID；重启返回失败或直接抛异常均进入补偿。
  包内失败注入同时发现并修复了 ServiceLib 配置生成提前标记成功的问题：最终模板处理成功后才允许 `RetResult.Success=true`。
  错误的普通/TUN 模板及测速自定义出站最终处理必须返回失败，避免启动链沿用旧配置文件；上游合并时保留这一失败语义和回归测试。
- `SettingsEditorService` 接管批量设置、入站、内核、应用、测速、Xray 映射和路由策略编辑。
  领域值和规则统一端口偏移、凭据配对、Mux 范围和测速 URL；上游选项、范围语法及完整 Config 留在适配器。
  单项与批量保存使用相同验证和规范化，允许已禁用 Mux 的空值按读取结果往返。
  读取快照→应用字段→保存→失败恢复共用写锁；单项保存失败也恢复持久化和内存状态，并区分恢复失败。
  所有设置编辑按生命周期锁→写锁排序；应用和测速设置不要求运行状态正常，也不重启核心。
  统计服务在最终运行应用/补偿后读取最终配置，刷新失败保留成功持久化事实并记录日志。
- 简易 DNS、DNS 配置和完整配置模板已接入同一 `SettingsEditorService`。
  适配器在修改前检查存储记录，克隆完整上游实体并保留身份/未暴露字段；DB 写入失败和多文档部分写入使用原有 journal 快照恢复。
  纯 DB 文档编辑不再额外保存未变化的 JSON 配置。读取和 HTTP 映射位于适配器，应用命令只表示 Xray 配置。
  `DnsProfileSettings.ForRuntime` 与 `CoreTemplateSettings.ForRuntime` 按当前普通/TUN 模式比较生效内容，
  补上了 TUN 模板编辑的变更检测；名称、禁用文档和另一模式内容变化不重启当前核心。
- `CoreConnectionService` 接管节点选择、启动、停止和重启，以及监听就绪验证后的失败清理。
  `CoreConnectionState` 定义重启准入、重复启动、停止需求和无连接选择规则，状态为停止但仍有子进程时禁止直接选择。
  所有入口仍使用同一生命周期锁；HTTP、设置恢复、更新回滚调用同一服务。节点在锁内读取，避免排队前读取的陈旧节点参与启动。
  预检拒绝和预检异常不停止正在服务的内核；停止失败不启动新进程，启动就绪同时要求监听和受控子进程证据。
  启动失败/取消后的清理使用独立于请求的令牌，清理失败保留剩余进程身份和两段错误。
  ServiceLib 构造上下文、helper 许可、进程捕获与健康监测仍在基础设施适配器，不授予应用层额外执行权限。
  原有 `CoreRestartFlow` 已移除，原预检测试直接执行生产应用服务，避免维护仅供测试的平行流程。
- `RuntimeStartupService` 与 `RuntimeShutdownService` 接管宿主初始化、恢复启动意图和退出清理编排。
  `RuntimeRestartIntent` 保持原有序列化字段，恢复标记优先于更新标记；停止意图覆盖自动启动，首次设置未完成时禁止恢复连接。
  journal 恢复在组件初始化和所有后台写入之前完成；后台调度延后到启动恢复结束，避免慢速恢复与定时任务并发修改配置。
  恢复初始化失败保留标记，更新标记仍由外部健康验收消费；服务初始化后即登记退出清理资格，即使随后被取消也能清理资源。
  关闭按恢复交接→调度停止→操作排空→统计检查点→内核停止→检查点排空→配置保存→数据库关闭执行。
  超时或失败停止后续共享资源清理，统计短等待超时仍允许停止内核，但必须等写入结束才能关闭数据库。
  关闭总时间窗使用单调时钟；任务超时后的取消令牌仍可读取，退出时异步取消回调，避免回调阻塞突破总退出预算。
  进程、数据库、初始化上游组件、环境配置和关闭诊断状态仍由宿主适配器实现。
- `MaintenanceSchedule` 定义订阅、保存、清理、GeoFiles 和每日更新检查的周期与顺序；保持原有按完成后计时的节奏，不按休眠时长补跑。
  `ScheduledMaintenanceService` 管理单个循环、逐项错误隔离和取消排空，具体任务通过适配器复用已有订阅和更新应用流程。
  同一周期的 GeoFiles 更新间隔取一次快照；一次任务失败不会跳过其他到期任务，请求取消则停止剩余任务。
  停止超时后保留任务所有权，禁止创建第二个循环；并发停止共享取消任务，所有执行和取消回调均完成后才允许释放资源和再次启动。
- `RegionalPresetService` 接管区域预设配置、GeoFiles 事务和运行应用之间的补偿编排。
  下载阶段不持有独占维护锁，开始时以共享操作租约和写锁捕获一致快照；应用时取得独占维护与生命周期租约。
  DNS、路由、旧选择和预设源的快照指纹必须仍匹配，下载期间发生本地修改时返回 `regional_preset_conflict`，不写入也不回滚新状态。
  不相关应用设置变化不影响暂存结果；上游完整 DNS/路由、下载降级和存储仍由 ServiceLib 适配器承担。
  配置写入失败先恢复配置；GeoFiles 失败先完成文件回滚再恢复配置/运行；运行应用失败沿用统一设置补偿，避免重复重启。
  文件回滚不完整会传入恢复服务，不能使用不确定的 GeoFiles 重新启动旧核心；响应分别记录文件与运行恢复结果。
  关闭令牌覆盖排队和下载，客户端取消不能打断补偿；下载租约在独占维护前释放，避免共享锁升级死锁。
- `CoreUpdateApplyService` 接管候选应用和失败恢复，`ModuleUpdateTasks` 接管单项/批量更新的任务准入与生命周期。
  候选完整验证在停止原内核之前；可信激活、本地替换、初始化、重启和提交顺序由应用层统一控制。
  helper 激活请求发出后即记录“可能已激活”，确认丢失时必须先取得可信回滚确认，不能只恢复本地文件并重启。
  `AlreadyCommitted` 表示保留两侧候选且健康未确认，不能报告回滚或更新成功；未知可信回滚结果明确失败且不改本地文件。
  取消后的补偿不继承请求令牌，取消停止也会结束临时运行状态；预备阶段无替换的失败不再误报已回滚。
  空闲目标不停止其他运行实例；文件恢复失败不能继续初始化/启动旧内核；候选/旧目录清理失败不撤销已确认提交。
  上游包验证、目录替换、helper 协议和 HTTP 进度映射保留在适配器；路径构造也包含在生命周期锁的 finally 范围内。
  目录恢复先确认备份存在且身份无歧义，再删除候选，缺失备份时保留唯一安装及故障证据。
  核心提交仍是逐目标事务，批量顺序不承诺撤销已经确认提交的更新。
- `CoreUpdateRunService` 接管单项更新的检查决策、暂存、独占应用、进度终态和暂存释放。
  只允许明确可用的候选进入下载，待兼容验证、当前版本和未知/失败决策不进入独占应用。
  共享操作租约覆盖检查与暂存，申请独占维护之前必须释放；关闭发生在两阶段之间时仍释放已持有的暂存包。
  `CorePackageStagingService` 统一下载→解包→可信认证→可执行版本探测→所有权交接的顺序；认证失败或取消不能执行下载的文件。
  目录创建也进入受保护的暂存流程，任何阶段失败都尝试丢弃可信暂存和本地文件，成功才把清理责任交给更新用例。
  完整上游检查结果、下载进度、文件路径与可信令牌保留在适配器；应用端只传递决策、版本与不透明产物。
  诊断失败不能掩盖原始异常、跳过清理或使已持久提交的更新回滚；原单项暂存委托流程已删除，测试直接调用生产应用服务。
- `UpdateBatchService` 统一核心、GeoFiles、程序更新的检查、暂存、应用与重启交接。
  一次独占维护租约覆盖批量工作，保留只读观察；先验证全部核心包，再完成规则事务和程序暂存，最后依次应用核心并交接程序更新。
  任一明确失败或未知检查结果阻止所有安装；等待兼容验证或当前部署不可安装的目标独立结束，不阻止其他可执行目标。
  每个目标的终态由应用用例持有，检查失败也会结束尚未执行的程序目标，不再用 UI 进度缓存反推完成状态。
  核心应用的结构化失败继续处理其他目标，但批量结果为失败；运行核心已成功更新时跳过重复的规则重载。
  程序交接后由更新助手完成最终确认；保留原有独立目标策略，核心失败不撤销已经提交的其他目标或禁止程序交接。
  任一暂存释放、文件清理或诊断失败不能跳过其他包的清理。原通用委托批量流程删除，回归直接验证生产用例。
- `UpdatePreferencePolicy` 定义可见选择替换、隐藏历史目标保留、精确大小写和显式预发布列表优先的规则。
  上游旧 Web 目标别名仍由适配器转换，领域不绑定上游程序名称；预发布选择与是否选入批量更新相互独立。
  `UpdatePreferenceService` 在同一写入范围内捕获完整配置、合并、保存和失败恢复，复用现有 journal 恢复端口。
  保存失败不再遗留已修改的内存选择；恢复未完成时不允许下一笔保存进入，避免旧快照覆盖后续写入。
  快照失败不修改配置；恢复失败单独返回 `rollbackDetail`，不能误报已恢复；未展示配置字段原样保留。
- `ApplicationUpdateService` 接管程序更新的准入、维护租约、暂存、交接和失败终态；单项和批量更新复用同一暂存与交接用例。
  `ApplicationPackageStagingService` 要求下载、校验、候选拷贝和所有权交接之间检查取消，失败时清理部分产物且保留原始异常。
  发布清单、可信 URL/资产匹配、SHA-256、RID、归档白名单、系统进程启动继续由基础设施负责。
  `ApplicationReleasePolicy` 定义预发布频道与同版本不同提交的更新规则；版本语法及排序由上游适配器提供。
  `ApplicationDeploymentPolicy` 定义容器、托管服务、只读目录与原生部署的安装资格；提示文案和平台探测留在 WebAPI。
  `ApplicationUpdateHandoffService` 将启动助手设为所有权分界：交接前失败分别清理运行意图和计划，交接后保留助手恢复文件。
  进度或日志异常不能阻止已交接后的正常退出；启动成功但确认失败仍尝试退出，不把候选收回或删除恢复资料。
  `ApplicationReplacementService` 管理助手侧替换、健康验证和旧版本恢复；部分文件恢复失败不能仅凭进程健康宣称恢复完成。
  健康确认后的清理失败不触发二次回滚；助手记录最终事务结果后，报告或意图清理异常也不能再次替换文件。
  原有部署限制保持不变，这不为 macOS 增加或启用上游 WebAPI 自更新安装能力。
- `BackupArchiveService` 负责配置落盘、快照捕获、压缩、大小准入及产物清理责任转移；备份大小/条目限制由 `BackupPolicy` 统一。
  调用方继续持有既有独占操作租约，恢复过程的安全备份复用该租约；落盘和快照捕获共用配置写锁，压缩在快照分离后释放写锁。
  SQLite 通过上游连接的在线备份接口取得一致数据库，包含已提交 WAL 页面；不把活动 WAL/SHM/journal 单独复制进归档。
  配置复制继续排除本机 API 认证资料，对大小写变体也排除；未知普通配置文件和上游字段保留。
  压缩器返回失败时也删除部分归档；快照清理或日志失败不撤销已经完整生成的备份。
  `BackupUploadService` 管理创建→上传→本地释放，上传失败仍尝试释放本地产物，清理错误不掩盖传输结果。
  WebDAV 配置接入统一设置编辑/持久化补偿，URL、用户名和目录去除首尾空白，省略密码保留原值，显式空字符串清空密码。
  `RestoreInputService` 在共享操作租约内接收上传/下载，无法取消的上游下载必须等待返回；关闭期间返回的产物清理后拒绝交接。
  共享接收租约在独占恢复前释放，避免锁升级死锁。WebDAV 检查、上传和下载共用传输锁，防止上游单例互相替换/关闭客户端。
- `BackupRestoreService` 接管归档校验、重启预检、安全备份、运行意图、停止/落盘、数据库关闭、配置替换和重启责任。
  预检拒绝或缺少必要的原生替换计划时不创建安全备份、不停止内核；安全备份失败也不修改运行状态。
  数据库第一次关闭尝试即转移到新宿主恢复，避免部分连接已关闭却在旧宿主中重新启动核心。
  关闭前取消/失败清理本次意图并恢复原运行；恢复不继承请求取消。统计采样器如已停止也会重新初始化。
  即使原意图是停止，只要仍有本进程拥有的核心进程，失败恢复也明确保持故障状态，不能停留在临时停止中或启动第二个核心。
  关闭后完成目录事务并请求重启；失败时保留恢复意图和安全备份，不在旧连接上恢复运行。
  暂存、归档和操作租约分别释放，清理/诊断失败不能跳过其余清理；旧的预检委托流程已删除，测试调用实际恢复用例。
  旧归档的已提交 WAL 页面先在线合并为独立数据库；没有所属数据库的日志拒绝恢复，替换数据库时移除候选目录中旧日志。
  目录交换或补偿失败时保留被移开的旧目录；只有确认替换成功才清理它，避免删除唯一旧配置。
- 订阅更新在下载后、保存后及通知前同时检查操作协调器的关闭状态和令牌。
  异步取消回调尚未传播到关联令牌时，也不能把已经进入关闭阶段的下载写成成功完成。
- WebAPI 的其余 Services 承担组合根、平台适配、文件事务、查询投影与防腐适配。ServiceLib 的 UpdateResult、
  ServerSpeedItem 与 HTTP TrafficView 在边界处转换，不进入领域程序集。
  更新枚举显式映射，未知上游值按 Failed 处理，兼容验证等待状态优先。
- `macos/Native/Sources/V2rayMDomain` 是独立、无目标依赖的 Swift target，
  保存 ProxyMode、ConnectionCoordinator 与 NetworkRecovery。
  V2rayMKit 通过类型别名保持调用兼容；HTTP 状态转换、网络错误分类仍由 Kit 承担。
- `V2rayMApplication` 是只依赖 Swift 领域层的原生应用层，时钟通过端口注入。
  `ObservationScheduler` 管理元数据观察的频率、取消和排空；同主题最多一个在途请求和一个最新待刷新闭包。
  强制刷新取消旧请求，待其返回后才启动最新请求；不会无限叠加尚未响应取消的 HTTP 工作。
  退出时保留并排空已取消观察任务，然后停止所属后端。观察失败仍保留最后有效数据，不触发代理断开。
  `NetworkRecoveryService` 接管刷新、模式对齐、重启提交、启动证据验证与端口重新绑定的顺序，
  通过 `NativeRecoveryRuntime` 获取领域观察和执行外部动作；每个步骤检查取消及恢复代际。
  AppModel 适配器仅在代际仍匹配时发布恢复读取的 operations/TUN 状态。
  `NativeShutdownService` 固定排空任务、恢复系统代理、确认 TUN 停止、停止所属后端的顺序；
  `TunnelStopEvidence` 要求 stopped 状态与空的所属进程集合同时成立，缺少 API 时不能跳过已启用 TUN 的停止确认。
  `NativeModuleUpdateService` 管理读取更新计划、按运行状态选择代理、保存偏好和提交更新；
  目标与预发布规则在 `NativeModuleUpdatePlan`，HTTP 路径与进度文案留在适配器。
  提交前取消不继续更新，后端已经接受的提交不因客户端随后取消而误报撤销。
  `ProxyModeService` 通过领域 `TunModeState`、`ProxyConnection` 和后端/偏好端口编排互斥模式切换及失败补偿。
  Kit 只转换 HTTP/helper 状态、提供系统接口与映射用户错误；断开路径保持单向关闭，失败不重启旧模式。
  `NativeStartupService` 编排代理恢复提示、所属后端启动、闲置 TUN 意图归一、首次观察与连接意图恢复；
  失败先停止所属后端再传播原错误。完整启动任务纳入退出排空，退出过程中不发布迟到的 ready 状态或启动轮询。
  `NativeCommandService` 统一普通命令和设置写入的观察/端口同步/失败清理；观察失败保留成功命令结果，
  清理错误不覆盖命令原错。`CommandFailurePolicy` 区分关闭重试、恢复重试和报告错误。
  设置写入跟踪完整的命令与收尾任务，退出不会在状态刷新或端口绑定仍进行时提前停止后端。
  `TunPreflightService` 与领域准入规则统一普通连接和模式切换的 helper/其他 TUN 检查。
  `NativePollingService` 负责周期观察、退出检测、关闭重试、恢复分派与观察失败退避；
  旧操作代数/恢复代际失效后不执行清理，物理断网不阻断本机诊断，观察失败不自动断开健康代理。
  更新完成由 `NativeModuleUpdateCompletion` 要求提交结束、相关后台任务结束和全部目标终态同时成立。
- 独立 Geo 更新由 `GeoUpdateRunService` 持有维护租约并编排规则替换、在用核心重启、文件回滚和不可取消的旧运行恢复。
  通知失败不阻断补偿，也不把已经提交的文件更新误报为回滚；文件备份、校验和交换留在基础设施事务。
  TUN 开关写入接入 `SettingsEditorService`，复用未暴露字段保留、变更指纹、持久化补偿与运行应用；helper 探测仍是平台前置检查。
- helper 保持独立权限上下文，不与普通后端共享进程启动权限。
- `CoreHealthEvidence` 统一状态查询和后台监视器的健康判定：运行状态必须同时有所属进程和可用监听器，
  启动/停止中的状态不由观察改写。`CoreHealthObservationService` 通过发布端口提交故障。
  适配器把快照身份比较与故障发布置于同一个同步边界，并与命令状态替换共用该边界。
  旧观察不能覆盖新连接或同值的新快照；并发故障观察只发布一次。状态响应仍是一次观察的快照，不能当作后续命令的授权。
- 后端 `RuntimeLogHistory` 承担序号、清空代际、单条截断和最旧记录淘汰，时间由外部提供。
  WebAPI `LogBuffer` 只负责并发保护、DTO 转换和有时间预算的正则查询；过滤不占写锁。
  原生 `BoundedLogHistory` 通过日志条目协议管理去重、字符/条数上限和最旧记录淘汰，
  Kit 的 `RollingLogBuffer` 保留原调用类型；HTTP 解码和 AppKit 文档渲染留在外层。

流量窗口缓存最后采样时间，避免每次 Add/Read 为查队尾枚举整个 Queue；
清空、时间倒退、超长采样与断档会同步清空时间缓存。加权、过期和计量单位保持不变。

## 依赖与合并约束

领域只保存业务事实和规则；应用层负责事务、取消、锁和用例顺序；基础设施实现
存储、进程、HTTP、helper 接口；展示层负责 DTO 与 UI 状态。新功能不得向领域层
反向引用 API 或上游模型。上游实现继续留在 ServiceLib，变化通过显式映射吸收，
持久化枚举、节点 ID、配置字段与 HTTP 契约不因目录调整改变。

`python3 scripts/check-ddd-boundaries.py` 检查领域引用方向，产品构建和 CI 均调用它。
`python3 scripts/test-ddd-boundaries.py` 用反例验证边界检查，并防止 Foundation 成为原生 I/O 绕过入口。
原产品边界扫描新增领域目录。构建来源摘要包含新程序集；打包仍要求同一源码快照。
后端程序集依赖测试提供编译产物层面的补充检查。

回归包括既有运行状态矩阵、设置失败回滚、流量加权与过期、未知更新状态拒绝、
兼容验证等待优先、原生恢复代际与迟到响应，以及 helper 权限和恢复测试。
测试、签名构建、安装、真实网络与公证结果必须单独记录。

### 后台版本检查的运行边界

隔离恢复烟雾测试确认：等待 SSE 心跳后可能碰到第一分钟后台版本检查，
此前该检查在网络请求期间持有共享操作租约，会延迟需要独占租约的设置写入。
现在由 `ScheduledUpdateCheckService` 编排三个阶段：保护范围内捕获更新偏好、代理端口和已安装版本；
释放运行租约后使用快照查询远端；重新进入保护范围，确认快照仍匹配才发布提示。
ServiceLib 的单目标检查接受可选的版本和代理端口快照，默认调用行为保留，减少上游合并接触面。
远端迟到响应不覆盖已经变化的配置/版本；单目标失败不跳过其他目标；取消后不发布结果。
完整任务仍由 `ScheduledMaintenanceService` 持有，关闭必须先排空计划任务，之后才能关闭共享资源。
回归使用实际操作协调器阻塞远端请求，验证独占设置和安装操作仍可进入。
隔离备份/恢复烟雾测试在 SSE 心跳后再次写入设置，覆盖原延迟位置。
原生调度、状态健康和日志保留已使用对应领域规则/应用用例，最终验证状态以审查文档指向的构建记录为准。
