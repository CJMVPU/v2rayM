# macOS 运行架构

`v2rayM.app` 包含 Swift 主程序、签名助手和 `Contents/Frameworks/libV2rayMXray.dylib`。应用以普通用户身份运行。普通代理和 TUN 都由同一 PID 中的 Xray 转发。旧版自定义节点配置了前置 SOCKS 端口时，同一动态库可以运行两套配置，分别维护 DNS、路由、出站标签和日志。

## 从节点到连接

1. Swift 从 v2rayM 自己的 SQLite 数据库、配置文件和节点文件读取完整记录，按节点、策略组、路由和 DNS 设置生成 Xray 配置。
2. 普通代理启动应用内监听器，系统代理模式将 macOS 代理偏好指向可用端点。TUN 模式由签名助手创建 utun，主程序将描述符交给 Xray，随后通过助手激活路由和 DNS。
3. 宿主使用会话身份关联状态、流量、日志和清理。恢复服务区分用户的连接意图与实际运行状态，在唤醒、网络变化和用户取消时检查操作代际。
4. 停止时恢复系统代理或 TUN 租约并确认结果。尚未确认的清理保留重试状态。

配置里的 `env:` 引用按配置解析，隧道描述符和资源目录由宿主管理。两套配置显式要求互不兼容的进程级参数时，启动会报告冲突键。用户的原始配置保存在数据库或原文件中。
