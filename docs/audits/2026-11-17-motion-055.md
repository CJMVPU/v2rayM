# v0.5.5 dashboard rendering lifecycle and frame pacing

- A single home render gate observes window visibility/occlusion, minimization,
  application hiding, display/system sleep, session switching and screen lock.
  Invisible homes release their visual subtree and cancel card/row tasks and
  display links. Backend telemetry continues; reappearance starts from its newest
  snapshot and fades in over 0.22 seconds instead of replaying queued animations.
- Preserve each solid front face once, with stable SwiftUI identity. Remove the
  former hidden full-content layout copy. Side layers exist only while the turn
  exposes thickness; back content mounts only when facing the viewer. Resting
  faces preserve their shadow/relief without those extra side/back subtrees.
- Replace the chart's 60 Hz animation timeline with an NSWindow CADisplayLink,
  requesting preferred/maximum 120 Hz where supported, adapting to lower-rate
  screens and screen changes. Only the drawing subtree observes frame ticks.
  The system still chooses actual cadence; a request is not an FPS guarantee.
- Cache settled traffic curve paths between data/scale/layout updates. Display
  ticks translate the cached paths; sample reveal and scale transitions retain
  smooth interpolated geometry. Avoid republishing equal card values.
- Retain seven centered rows, independent row cadence, data-ready staggered card
  flips, proxy-only node totals, dark styling and the existing physical appearance.

Evidence: `artifacts/reviews/2026-11-17-motion-055/`.
Tests cover every visibility blocker, single front lifetime, lazy back creation,
subtree removal, latest-data restoration, frame-rate ranges, previous lifecycle
races, chart edge continuity and live compositor snapshots. Release performance
harnesses use copied 0.5.4/0.5.5 UI sources, synthetic telemetry and sequential runs;
no proxy/TUN is started. Display callback counts are not compositor FPS. IORegistry
GPU utilization is system-wide, not an app-exclusive measurement.

Signed product/packaged loopback, mounted DMG readback, installed-app hash checks
and cleanup receipts are separate. The user authorized commit/push and a package
without replacing the installed app, without waiting for remote CI. Real TUN
acceptance and notarization are not claimed.

Measured on the unlocked 120 Hz M5 Pro desktop with the same one-second speed /
seven-row replacement workload: hidden CPU 32.13% → 0.61%, minimized CPU 34.13% →
0.63% (one logical core = 100%); new hidden/minimized display callbacks were zero.
Steady visible chart callbacks reached 119.58 Hz; dense row replacement reached
98–99 Hz. Visible steady CPU increased 23.20% → 34.99% with the higher requested
cadence. This is a background efficiency improvement, not an across-the-board
power reduction. System GPU averages are not app-exclusive and fluctuate even
with the blank window; the detailed report preserves those attribution limits.
