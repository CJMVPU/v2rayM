# DDD 复查、主窗口 UI 与 0.4.5

## 范围与结论

基于 `d751809d` 复查领域/应用依赖方向、运行租约、取消与退出、核心启停、设置补偿、
更新/恢复提交边界、节点查询和原生任务所有权。继续采用模块化单体；没有新增引擎、进程、
数据库、依赖包、通用仓储或消息总线。本轮不修改 ServiceLib 源码，也不导入上游提交。
平台 I/O 和完整上游实体留在适配器；不为分层再复制全部存储模型。

## 修复与简化

1. **CI 暴露的退出竞态。** 运行 `43699550015` 在
   `SpeedTestCoordinatorTests.ShutdownCannotDrainWhilePreparationStillReadsStorage` 失败。
   `StopAndDrainAsync` 先关闭接纳，再异步取消 linked token；测速准备可能在回调传播前完成。
   现在在准备结束和接纳/运行前核对 `IsStopping`，保持整个准备与测速的租约。
   测试增加“先关闭接纳、延后取消”分支，不依赖睡眠或放宽断言。
2. **诊断不应改变业务结果。** 核心启停和设置补偿中的日志异常可能跳过清理，
   或把已成功的进程操作变成失败。合并原更新、备份中的两套重复诊断保护为一个
   `ApplicationDiagnostics`，补齐设置/恢复/运行路径；核心状态通知失败也不再回滚健康核心。
   真正的进程、文件、配置错误仍正常传播或补偿。
3. **路由编辑器原子切换。** 规则读取成功后才一起替换方案 ID、文档与规则；失败保留原编辑文档，
   避免把旧规则误存到新方案。添加读失败/成功的回归，加载操作使用独立成功提示。
4. **移除无用查询包装。** `ProfileQuerySnapshot` 的订阅列表和选中分组没有消费者，
   移除该包装，返回实际需要的只读节点条目；HTTP 字段及排序语义不变。
5. **边界守卫。** 检查 Swift 属性/限定 import，禁止 ServiceLib 引用本地 DDD 项目；
   对合法 Swift target 换行保持兼容。新增负面依赖和格式化回归。
6. **可诊断的 CI。** 分开 ServiceLib 和 WebAPI 测试步骤，失败时也上传测试报告，保留失败退出码。

## 主窗口体验

- 设置总览采用统一分组卡片；网络配置入口、更新动作与进度按功能排列。
- 参数、路由、DNS、节点配置与导入复用主窗口内容区；没有编辑 sheet 或独立窗口。
- 编辑期间通过返回入口处理未保存确认，避免导航销毁草稿；保存状态、错误和进度在当前区域显示。
- 开关、字段和选择器统一对齐；参数保留四分类、MTU 预设及自定义输入，DNS 分开常规/自定义。
- 保留固定窗口、标题栏模式控制、固定节点列/底栏、字体、日志历史及禁用感知 hover。
- 本机验收脚本读取 `VERSION`，避免版本升级后仍硬编码旧版本。

## 上游合并影响

本轮应用层修复不要求改写上游 ServiceLib；未调整 HTTP 契约、持久化枚举或数据表。
保留 Git fork/remotes，合并仍需逐项审查受保护文件。
新增上游字段应只触及适配器与对应输入/展示，不允许把 ServiceLib 反向绑定到本地工作流。
原生展示拆分为 `SettingsPage`/小型公共视图，业务命令继续通过 AppModel 的现有接口执行。
