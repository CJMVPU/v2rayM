# macOS TUN 助手

普通代理由主程序直接运行。真实 TUN 需要由 `SMAppService` 管理的签名助手创建系统隧道。首次使用时，在设置页注册并按 macOS 提示授权后台服务。升级后若提示助手协议不匹配，使用“检查与修复”。

## 一次 TUN 会话

1. 应用以当前会话的 UUID 打开 XPC 连接，助手检查签名调用方、请求格式及可用租约。助手创建 utun，并返回接口名称和文件描述符。
2. 主程序将描述符交给进程内的 Xray。内核就绪后，应用用同一个令牌请求助手激活网络租约。代理协议、节点选择、流量转发和 Xray 日志由主程序负责。
3. 停止或连接中断时，助手尝试恢复本会话的路由和 DNS。客户端可通过新的 XPC 连接查询原令牌的清理结果。仅在恢复获得确认后释放待清理状态。
4. 助手按需运行。助手处理活动租约和待恢复的网络状态。会话清理完成且没有客户端后，助手按空闲策略退出。

应用与助手需要满足团队签名和调用方身份要求。Xray 随应用签名和升级。助手注册、授权和修复使用应用内设置入口。

## 验证

助手策略与网络租约测试使用 `swift test --package-path macos/TunHelper`。打包回环通过本地套接字对验证应用内 TUN 转发。对签名 App 可运行只读预检：

```sh
scripts/network-check tun-acceptance --check-only --app /Applications/v2rayM.app
```

真实 utun、休眠、切网和系统路由/DNS 恢复需要单独验收。执行 `scripts/验证新版v2rayM.command` 前关闭其他 VPN/TUN 和系统代理。该入口使用隔离数据副本，并记录启动、转发、重新连接与停止恢复的结果。构建及签名要求见 [README](build-and-test.md)。
